# You2Bi

<img src="apps/web/public/you2bi-icon.png" width="96" alt="You2Bi" />

把 YouTube 视频制作成带中文字幕、中文配音的视频，并交给 bilibili 发布队列。当前版本 **0.1.28**，主要运行环境为 Windows x64。

适合需要持续处理某些频道、批量制作视频的人。你可以先处理一条视频，确认翻译、声音和投稿设置，再开启频道监控。

## 能做什么

- 粘贴单个 YouTube 视频地址，创建自动化任务。
- 添加 YouTuber，显示头像、名称和基础信息，批量选择历史视频。
- 定时检查频道的新视频，将符合条件的新视频放入队列。
- 下载、分离人声、语音识别、翻译、准备参考音频、生成中文配音、混音和导出。
- 使用原视频封面，翻译标题和简介，选择投稿分区和标签。
- 显示处理进度、配音已保存段数、生成速度和预计剩余时间。
- 从有效断点续跑。发布详情可查看各制作阶段用时，队列显示累计制作用时。
- 公开发布确认后可清理素材。已发布稿件可重新制作并替换视频源，之后由 B 站重新审核。

## 第一次使用

### Windows 程序

从 [Releases](https://github.com/lhl1/You2Bi/releases) 获取已发布的程序包。源码页的绿色 Code 按钮下载的是源代码，需要自己构建。

普通程序包解压后运行 You2Bi.exe，根据初始化页面选择数据目录并准备依赖和模型。第一次下载模型需要网络和较多磁盘空间。

如果拿到包含模型与 Python 的整合包，请完整解压到较短的本地路径，例如 D:\You2Bi，双击“启动 You2Bi.cmd”。整合包首次启动会修复 Python 的本地路径。搬到另一台电脑后仍使用这个启动入口。

整合包的目录结构如下。

~~~text
You2Bi-Windows-x64/
  启动 You2Bi.cmd
  launch.ps1
  app/                 桌面程序
  data/youdub/
    runtime/           Python、依赖和 FFmpeg
    models/            识别、配音与分离模型
  README.md
~~~

运行后，账号、设置和新任务会保存在整合包自己的 data 目录。移动前从托盘完全退出程序。新电脑需要自行登录 B 站、配置翻译服务和 YouTube 凭据。

### 电脑要求

| 项目 | 说明 |
|---|---|
| 系统 | Windows x64，当前整合包面向 Windows 10/11 |
| 显卡 | 原生配音支持 CPU/CUDA。NanoVLLM 需要兼容 CUDA 的 NVIDIA 显卡 |
| 显存 | 本机 RTX A2000 12GB 已实测双路和四路，整片峰值接近 12GB。其他显卡需实际验证 |
| 磁盘 | 需容纳解压后的程序、模型和下载视频，长视频中间文件会继续占用空间 |
| 网络 | 能访问 YouTube、模型下载站点和 bilibili |
| 运行库 | 若系统提示缺少 VCRUNTIME/MSVCP，安装微软 Visual C++ 2015–2022 x64 运行库 |

CPU 方案速度取决于处理器。NanoVLLM 加速环境在本机 Python 3.12、PyTorch 2.8.0+cu126 上验证。换电脑后应先做短视频测试。

## 用一条视频走完整个流程

1. 打开“发布设置”，登录自己的 B 站账号。
2. 设置 YouTube 代理。默认端口为 **7897**，对应本机 HTTP 代理。代理软件端口不同就修改，填 0 表示直连。
3. 配置翻译服务，可使用已选大模型或界面提供的机器翻译服务。Google Cloud、微软等服务的密钥和配额按各服务商要求设置。网页翻译可能限流。
4. 如果 YouTube 要求验证，到 YouTube 登录凭据处导入已登录浏览器导出的 Netscape cookies.txt，或配置已有的 Edge 同步入口。
5. 粘贴视频地址并加入队列。等待下载、制作、上传和稿件审核。
6. 在发布详情查看当前阶段、错误、重试入口及 B 站稿件链接。

程序会加密保存 YouTube 凭据，后续任务自动使用。登录状态可能失效，失效时需要重新登录或同步。Windows 加密凭据与当前用户有关，迁移电脑后重新配置。

## 频道监控和批量处理

打开独立的监控列表，添加频道主页、@handle 或 UC 开头的频道 ID。添加后可以选择历史视频，也可以只监控此后发布的新视频。

检查间隔默认 5 分钟。频道视频页支持多选和加载更多，已有任务会跳过。直播、尚未发布的视频等会按列表中的可选状态处理。

若 @handle 页面暂时打不开，程序会尝试通过 YouTube 公开搜索中的精确 handle 确认固定频道 ID，再读取视频列表。无法唯一确认时需要提供固定频道链接。

## 翻译、配音与导出

翻译全局同一时间只处理一条视频任务，视频内部可以批量翻译。断点中已保存的有效译文会继续复用。

配音档位可在工作流或自动化运行设置中选择。

| 档位 | 用途 |
|---|---|
| 原质量 | 原生 VoxCPM2，10 步 |
| 均衡 | 优先 8 步，短句及异常结果采用质量回退 |
| NanoVLLM 双路 | 10 步，同一视频同时处理最多两段 |
| NanoVLLM 四路 | 10 步，同一视频同时处理最多四段 |

NanoVLLM 遇到显存或上下文容量问题时会降低并发，必要时回退原生配音，复用有效的已保存片段。长句、长参考音频与其他 GPU 软件会影响速度和显存。

配音进度约每 3 秒读取一次，显示“已保存 X/Y 段”，只有处理并写入文件的片段才计入完成。首段之前会有模型加载时间。

默认下载分辨率上限为 1080p，可在设置中调整。视频编码器可选择自动、CPU 或机器支持的 GPU 方案。

成品先测量响度，低于 −20 LUFS 时才尝试提升至约 −16 LUFS，同时限制峰值。正常响度、较大响度和静音音轨沿用当前响度。

## 发布到 bilibili

配音稿件标题采用 [中配] 加中文标题。投稿说明包含原视频、原作者、发布日期、视频链接和原介绍的中文翻译。封面使用原 YouTube 封面，分区和标签根据内容选择，并可在界面修改。

“成片已导出”之后还需上传、提交稿件、等待审核。以发布详情的审核状态和实际 B 站稿件为准。

制作总用时是下载至导出各已完成阶段的记录用时之和。排队、上传、投稿和审核时间分别在其对应流程中处理。旧任务缺少时间戳时会显示待记录，素材清理后使用已保存的用时摘要。

请使用有权处理、配音和发布的内容，并按照平台要求标明来源。首次正式使用建议检查一条完整成片的译文、发音、字幕与音画同步。

## 常见问题

**下载要求登录或提示机器人验证**

检查代理是否可用，再检查 YouTube 登录凭据。程序中的访问检查可以帮助判断当前登录是否可用。

**配音进度暂时停住**

先看当前片段和已保存段数。模型加载、长句和单句重试会花时间。中断后使用继续任务，程序校验断点后补齐缺失片段。

**NanoVLLM 报显存不足**

关闭其他占用显卡的软件，选择双路，或者使用原质量档。程序也会自动降低并发。较低显存机器应先验证短视频。

**导出了视频，B 站还没看到**

打开发布详情查看上传、投稿、审核阶段。需要处理账号或文案时按照对应提示重试。

**换电脑后 Python 启动失败**

使用整合包的“启动 You2Bi.cmd”，它会按当前目录修复运行路径。确认文件完整解压，路径可写。显卡驱动和系统运行库需要在新电脑安装。

**旧任务没有各阶段用时**

有时间戳的历史任务可读取记录。已清理且从未保存用时的任务无法还原准确耗时。

## 开发者构建

需要 Git、Node.js 24、npm，以及构建 B 站上传组件所需的 Rust 工具链。编译原生依赖可能需要相应 Windows 构建工具。

~~~powershell
git clone --recurse-submodules https://github.com/lhl1/You2Bi.git
cd You2Bi
powershell -ExecutionPolicy Bypass -File scripts/build-youdub2bi.ps1
~~~

构建输出位于 dist/release-版本号。详细依赖见 package.json、apps/harness/package.json 和 backend/requirements。

本地已有原生组件及框架构建结果时，可依次执行。

~~~powershell
node apps/harness/build.mjs
node apps/harness/build-desktop.mjs
node apps/harness/package-desktop.mjs --dir
~~~

NanoVLLM 环境安装脚本为 scripts/install-nano-voxcpm.ps1。它安装在应用专用环境中。该脚本目前固定本机验证过的 Windows/Python/PyTorch 组合，其他组合需要自行验证。
